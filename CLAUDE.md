# Project-specific instructions

This is a **Bedrock-based WordPress** installation configured for deployment on **Clever Cloud**. It uses Composer for dependency management, with WordPress core and all plugins/themes managed as Composer packages via [WordPress Packagist](https://wpackagist.org).

## Commands

### Local Development (DDEV)

```bash
ddev start                    # Start the local environment (nginx-fpm + MariaDB 10.11)
ddev stop                     # Stop the environment
ddev restart                  # Restart containers
ddev launch                   # Open the site in browser (https://vitrine-clever.ddev.site)
ddev ssh                      # SSH into the web container
ddev exec wp <command>        # Run WP-CLI commands inside the container
ddev composer <command>       # Run Composer inside the container
```

### Dependency Management

```bash
composer install              # Install dependencies from composer.lock
composer update               # Update dependencies and regenerate composer.lock
composer require wpackagist-plugin/<slug>:<version>   # Add a plugin
composer require wpackagist-theme/<slug>:<version>    # Add a theme
```

**Important**: Never install plugins or themes through the WordPress admin. All plugins and themes must be managed via `composer.json`.

### Linting / Code Standards

```bash
composer test                 # Runs phpcs (PSR-2 standard, excludes web/wp/ and vendor/)
vendor/bin/phpcs              # Run PHP CodeSniffer directly
```

## Architecture

### Folder Structure

```
vitrine-clever/
├── config/
│   ├── application.php       # Main wp-config equivalent (CleverCloud env vars)
│   └── environments/
│       ├── development.php   # Enables WP_DEBUG, SAVEQUERIES
│       └── staging.php
├── clevercloud/
│   └── php.json              # Sets webroot to /web for CleverCloud deployment
├── web/                      # Document root (docroot in DDEV)
│   ├── app/                  # wp-content equivalent
│   │   ├── mu-plugins/       # Must-use plugins (bedrock-autoloader, s3-uploads-filter)
│   │   ├── plugins/          # Composer-managed plugins (gitignored except elementor-pro, formidable)
│   │   ├── themes/           # Composer-managed themes (gitignored)
│   │   └── uploads/          # Media (redirected to Cellar S3 in production)
│   ├── wp/                   # WordPress core (gitignored, Composer-managed)
│   └── wp-config.php         # Minimal bootstrap — do not edit
├── vendor/                   # Composer autoloader and PHP deps (gitignored)
└── php.ini                   # PHP overrides (upload_max_filesize=32M, memory_limit=256M)
```

### Configuration

- **Environment detection**: `WP_ENV` env var (`development`, `staging`, `production`)
- **Database (CleverCloud)**: Uses `MYSQL_ADDON_*` environment variables
- **Database (local DDEV)**: Auto-configured via `web/wp-config-ddev.php` (generated by DDEV)
- **Media storage (production)**: Cellar (S3-compatible) via `CELLAR_ADDON_*` env vars; the `s3-uploads-filter.php` mu-plugin redirects the endpoint away from AWS
- **File modifications disabled in production**: `DISALLOW_FILE_MODS` and `DISALLOW_FILE_EDIT` are `true` by default; overridden to `false` in `development.php`

### Key Conventions

- WordPress core lives in `web/wp/`, content in `web/app/` (not the standard `wp-content/`)
- `WP_CONTENT_DIR` is set to `web/app` and `WP_CONTENT_URL` to `{WP_HOME}/app`
- The `bedrock-autoloader.php` mu-plugin allows regular plugins installed in `web/app/plugins/` to be autoloaded as mu-plugins
- Two plugins are committed directly to git (not Composer-managed): `elementor-pro` and `formidable`

### Deployment (Clever Cloud)

- Push to the linked git remote; CleverCloud runs `composer install` automatically
- Webroot is configured in `clevercloud/php.json` as `/web`
- Required env vars on CleverCloud: `WP_ENV`, `WP_HOME`, `WP_SITEURL`, `MYSQL_ADDON_*`, `CELLAR_ADDON_*`, WordPress salts (`AUTH_KEY`, etc.)
- Dependabot is configured to check for Composer updates weekly

### WordPress Updates

**NEVER** run a global `composer update`. Instead, update each package independently like that : `composer require wpackagist-plugin/the-plus-addons-for-elementor-page-builder:^1.2`.
**ALWAYS** provide a specific version for the update.
**Do not** commit the `composer.lock` file. It is automatically generated on Clever Cloud deployment.
